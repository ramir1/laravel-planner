# Laravel Planner

Планировщик **одноразового отложенного запуска artisan-команд** для Laravel с хранением в БД.

В Laravel есть очереди (в том числе отложенные job) и scheduler для повторяющихся команд. Но отложенный job
живёт внутри бэкенда очереди: его не видно, его нельзя отменить, он теряется при очистке очереди. Planner
хранит каждый запланированный запуск в таблице: команду можно поставить на нужный момент, объединить запуски
в группу, отменить и посмотреть, чем каждый закончился.

```bash
php artisan planner:at "2026-10-08 03:00" "anonce:bump 15" --group=anonce:15
```

Полная документация (API, конфигурация, примеры) — в [README.md](README.md).

## Коротко

1. `composer require ramir1/laravel-planner`, `php artisan migrate`. Должны работать scheduler и воркер очереди —
   `planner:run` регистрируется в scheduler автоматически (каждую минуту).
2. Планировать можно любую artisan-команду; о планировщике она ничего не знает, модели передаются по id
   (`anonce:bump {anonce}`). Планировщик только запускает команду и записывает результат: код `0` — `done`,
   иной код или исключение — повтор через `backoff`, после `max_attempts` — `failed`; вывод команды — в `message`.
   Бизнес-решения («неактуально», «отменить остальные запуски» — `Planner::cancelGroup()`) принимает сама команда.
3. Постановка: `php artisan planner:at "+2 hours" "cache:clear" --group=maintenance` (время — всё, что понимает
   `Carbon::parse()`) или из кода `Planner::schedule('anonce:bump', now()->addDay(), ['anonce' => 15], group: 'anonce:15')`,
   `Planner::scheduleMany()`. Управление: `pending()`, `lastRunAt()`, `cancelGroup()`. `source` — необязательная
   связь «откуда взялся запуск» (например, оплаченная позиция заказа).
4. Выполнение: каждую минуту `planner:run` берёт созревшие запуски по возрастанию `run_at`, атомарно переводит в
   `running` и отправляет job в очередь; воркер вызывает команду через `Artisan::call()` в своём процессе (без
   нового PHP-процесса, накладные расходы ~0.1 мс). Воркеры выполняют запуски параллельно: группа — для отмены,
   а не для порядка.
   Пропущенные запуски: запуск созрел, если он `pending` и `run_at <= now()` (проверка раз в минуту). Если сервер
   был выключен, после включения первый `planner:run` отправит все пропущенные запуски. Ограничения «слишком
   поздно» нет — актуальность проверяет сама команда. Запуск, прерванный выключением, через `stuck_after`
   вернётся в `pending` и выполнится заново — команды должны спокойно переносить повтор. `run_at` хранится в часовом поясе приложения (`app.timezone`).
